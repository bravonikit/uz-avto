# Парсер Instagram

Скачивает посты с объявлениями о продаже авто из Instagram.
Отдельная часть проекта на Python, к сайту (Next.js) отношения не имеет.
Посты получает [gallery-dl](https://github.com/mikf/gallery-dl).

## Первый запуск

Все команды выполняются из папки `parser/`:

```bash
cd parser

# 0. Если в начале строки терминала видно (base) — это conda, выключите её
conda deactivate

# 1. Создать виртуальное окружение (один раз).
#    Это отдельная «коробка» с библиотеками только для парсера.
python3 -m venv .venv

# 2. Включить окружение (каждый раз в новом окне терминала).
#    В начале строки появится (.venv).
source .venv/bin/activate

# 3. Установить библиотеки (один раз и после изменений requirements.txt)
pip install -r requirements.txt
```

**Вход в Instagram:** откройте instagram.com в **Safari** и войдите.
Парсер берёт вход оттуда (cookies), пароль в проекте не хранится.

> Если появится ошибка доступа к cookies Safari: Системные настройки →
> Конфиденциальность и безопасность → Полный доступ к диску → включите
> для приложения терминала (Terminal или VS Code).

## Официальный API вместо входа через Safari

Если в `.env` есть токен, `download.py` берёт посты через официальный API Meta
(Business Discovery), а не через gallery-dl. Настройка один раз:

```bash
python ig_api.py setup                    # спросит App ID, App Secret и токен
python ig_api.py test auto_sale_abdulloh  # проверка на одном аккаунте
python ig_api.py status                   # сколько дней осталось у токена
```

Токен живёт 60 дней и продлевается сам во время прогона. API видит только бизнес
и авторские аккаунты. Чтобы вернуться к gallery-dl, сотрите `IG_ACCESS_TOKEN` в `.env`.

## Какие аккаунты парсим

Список в `accounts.txt`, по одному на строку (без @). Строки с `#` пропускаются:
так можно временно выключить аккаунт, не удаляя его.

## Всё одной командой

```bash
./run_daily.sh
```

Скачать новые посты, найти цены, выгрузить на сайт и показать статус.
Лог каждого дня: `data/logs/ГГГГ-ММ-ДД.log`.

## Каждый день автоматически

Один раз:

```bash
./install_schedule.sh       # включить (каждый день в 12:37)
./install_schedule.sh off   # выключить
```

Время меняется в начале `install_schedule.sh` (HOUR, MINUTE), после правки
запустите его ещё раз. Если Мак в это время спал, прогон начнётся после пробуждения.

Чтобы прогон по расписанию мог прочитать вход из Safari, дайте `/bin/bash`
полный доступ к диску: Системные настройки → Конфиденциальность и безопасность →
Полный доступ к диску → «+» → Cmd+Shift+G → `/bin/bash`.

## Что скачано

```bash
python status.py
```

Таблица по каждому аккаунту: когда последний раз скачан, сколько новых постов,
сколько всего, дата самого свежего поста, ошибки. То же в `data/status.csv`.
Данные лежат в `data/state.json`.

За один запуск `download.py` берёт до 30 аккаунтов (`MAX_ACCOUNTS_PER_RUN`):
сначала ни разу не качавшиеся, потом самые давние. Следующий запуск продолжит
с тех, до кого очередь не дошла. Посты старше 1 сентября 2026 не берутся.

Паузы случайные: 4-6 с между запросами, 1-3 с между картинками,
60-120 с между аккаунтами. 30 аккаунтов занимают примерно час.

## Запуск

```bash
source .venv/bin/activate
python download.py        # 1. скачать посты всех аккаунтов
python extract_price.py   # 2. найти цены
python export_to_site.py  # 3. выгрузить на сайт
```

Любой шаг можно запустить для одного или нескольких аккаунтов:
`python download.py auto_sale_abdulloh other_shop`.

У каждого аккаунта своя папка:

- `data/<аккаунт>/raw_posts.json` — по одной записи на пост: аккаунт, ссылка,
  дата (UTC), описание, тип (`photo`, `carousel` или `reel`), ссылка на картинку;
- `data/<аккаунт>/images/<shortcode>.jpg` — первая картинка поста (у рилса превью).
  Видео не скачиваются;
- `data/<аккаунт>/prices.json` — найденные цены и первый взнос (`down_payment`).

Пост без цены, в котором есть год, пробег или первый взнос, считается объявлением
без цены: его разбирает ЛЛМ (`python llm_parse.py todo`), и на сайте он показывается
как «Цена по запросу». Посты без цены и без таких признаков считаются анонсами.

**Дополнительные поля.** `python enrich.py` ищет в тексте поста тип цены (под заказ,
CIP, без растаможки), топливо, цвет кузова и салона, город и дописывает их в
`data/llm_parsed.json`. Берётся только то, что продавец написал сам. Запускать после
`llm_parse.py apply` и перед `export_to_site.py` (в `run_daily.sh` уже стоит).

**Дубли.** Если продавец выложил одну машину несколько раз, `export_to_site.py`
оставляет на сайте только самый свежий пост (сколько убрано, видно в конце вывода).
Дубли между разными продавцами пока остаются.

**Странные цены.** `export_to_site.py` прячет цену, если она не похожа на правду:
свежая машина дешевле 3000$ или цена в разы отличается от такой же модели у других
продавцов. Объявление остаётся на сайте с подписью «Цена по запросу». Список скрытых
цен с причиной: `data/price_suspects.json`. Если цена на самом деле верная (или вы
узнали настоящую), впишите её в `data/price_overrides.json`:
`{"DfJ3t5bjOKV": 55000}` задаёт цену, `{"DfJ3t5bjOKV": null}` убирает её.

`extract_price.py` в конце печатает таблицу по аккаунтам. Если у нового аккаунта
много «без цены», он пишет цену в другом формате: примеры таких постов
печатаются выше таблицы, по ним дописываем правило в `extract_price.py`.

Shortcode — код поста из ссылки: у `instagram.com/p/DAbc123/` это `DAbc123`.

Повторная скачка не затирает старые посты: новые добавляются к уже скачанным.

Настройки вверху `download.py`: `POSTS_LIMIT` (последних постов с аккаунта, сейчас 25), `DELAY_SEC`
(пауза между запросами), `ACCOUNT_DELAY_SEC` (пауза между аккаунтами).

## Telegram каналы

`tg_download.py` качает посты публичных каналов из `tg_accounts.txt` через открытую
веб версию t.me/s/<канал>: без входа и без ключей. Данные лежат в `data/_tg/<канал>/posts.json`.
Посты за 14 дней перечитываются при каждом запуске, за 90 дней раз в неделю: правки текста уходят в `history`,
удалённые посты получают `removed_at`.

```bash
pip install -r requirements.txt   # один раз, добавилась библиотека beautifulsoup4
python tg_download.py             # все каналы
python tg_download.py azaavtoo    # один канал
python test_tg_download.py        # проверка разбора
```

Пока посты Telegram только копятся, на сайт они не выгружаются.

## Разбор Telegram и выгрузка на сайт

```bash
python tg_parse.py        # посты Telegram → объявления: data/_tg/listings.json
python export_to_site.py  # Instagram и Telegram вместе → сайт
python test_tg_parse.py   # проверка разбора
```

`tg_parse.py` сырой слой не меняет. Каждый пост с текстом получает вид: `listing` (конкретная машина),
`catalog` (под заказ или прайс по комплектациям), `sold_notice` («продано» отдельным постом), `other`.
Разбор по каждому посту лежит в `data/_tg/<канал>/parsed.json`.

Дубли убираются в два шага: внутри канала (машину выложили повторно, прошлые цены идут в `price_history`)
и между площадками одного продавца (пост в Instagram и пост в Telegram про одну машину дают одну карточку,
ссылка на второй пост в `also_at`). Дубли между разными продавцами пока не склеиваются.

`./run_daily.sh` делает всё это сам после скачивания.
